# AI Use Disclosure

This document describes where and how AI tools were used in this replication project,
how the AI-generated output was verified, and the important AI errors that were
corrected during the work.

---

## 1. Where and how AI was used

| Area         | What was produced with AI                                                                                                                                                                                                                                                                                                                   |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Code**     | All replication code was generated by an AI assistant (Claude, via Claude Code): the data-cleaning script (`code/others/clean_data.py`), the Table 2 / Table 3 & 4 / Figure 1 scripts, the heterogeneous-DiD extension (`code/others/het_did.py`), and the master script (`code/run_all.py`). I then reviewed, corrected, and ran the code. |
| **Analysis** | Part of the analysis — interpreting outputs, cross-checking reproduced values against the paper, and drafting the interpretation of the heterogeneous-DiD results — was done with AI assistance.                                                                                                                                            |
| **Writing**  | Parts of the replication report (`report.pdf`) were drafted with AI assistance and then reviewed/edited by me.                                                                                                                                                                                                                              |

The AI was used as a *drafting and coding assistant*, not as a substitute for
verification: every number and every script was checked by me before being accepted.

---

## 2. How AI-generated code, analysis, and writing were checked

1. **Execution from a clean state.** Every script was run end-to-end and confirmed to
   produce the expected files (`data/processed/*.csv`, `outputs/tables/*.md`,
   `outputs/figures/*.png`).
2. **Cross-checking against the paper.** The reproduced values were compared line by
   line with the paper's published numbers, e.g. the Table 3 DiD estimate (2.75 vs.
   the paper's 2.76), the Table 4 coefficients, and the sample size (357 vs. 357).
3. **Sanity checks on the data.** Store-closing counts were verified against the paper
   (6 closed stores, 4 temporarily-closed stores), and group means (NJ vs. PA) were
   checked for each wave.
4. **Reading and editing.** I read all generated code and text, and edited or
   corrected anything that was unclear, incorrect, or inconsistent.

---

## 3. Important AI errors or suggestions that were corrected or rejected

### 3.1 Path handling in `run_all.py`

- **What happened.** The initial version of `run_all.py` relied on the `__file__`
  variable to locate files, which raises an error when the code is run inside a
  Jupyter environment.
- **Why it was wrong.** `__file__` is not reliably defined in Jupyter/notebook
  contexts, so the script failed before doing any work.
- **How it was corrected.** The script was rewritten as a standalone file that
  auto-locates the repository root, with an explicit, documented run baseline (run
  from the repository root: `python code/run_all.py`).

### 3.2 Scaling of percentage variables in Table 2

- **What happened.** Percentage-type variables that are stored as proportions in
  `[0, 1]` were initially reported as raw fractions, and the full-meal price
  (`pentree`) was mistakenly multiplied by 100.
- **Why it was wrong.** The proportion variables (store-type shares, the full-time
  employee share, the share of stores with starting wage = $4.25, and the
  recruiting-bonus share) needed to be multiplied by 100 to be reported as
  **percentage points**, while the meal price is a dollar amount and should **not** be
  scaled.
- **How it was corrected.** All 0–1 proportion variables are now multiplied by 100
  before output; the meal price is kept in its original dollar units.

I rejected the AI's initial handling of both issues and directed the corrections
described above. No AI-generated number was accepted into the report until it matched
the paper or could be independently verified.
